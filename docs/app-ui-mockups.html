dsh-remote-relay · App UI 设计案 v1 · 2026-09-30

手机 App 界面设计
Material 3 · 深色优先 · 状态色语义

App 是 relay 的原生客户端（Flutter），界面围绕一件事组织：每台机器的连接状态一眼可读。设计语言取 Flutter 原生的 Material 3，深色优先、浅色随系统；色彩系统里只有三种语义状态——绿（已连接）、琥珀（重连/临期）、红（失效/危险），主色翡翠绿只用于可执行动作，不与状态色混用。

01

设计语言与 Token

深色主题为默认主题（运维/监控工具的主场景）；浅色主题由同一套 seed 色生成，随系统切换。等宽字体（JetBrains Mono）专用于 sessionId、relay URL、job id 与证书指纹——凭证明材料永远和普通文案区分开。

03

状态与异常的界面行为

会话过期不是意外，是这套安全模型的日常节律——从续期到失效，每个节点都有明确的界面应答，不让用户猜。

24 小时会话生命周期（倒计时芯片视角）
  1. 刚续期 · ~24h

    芯片绿色/中性，显示剩余时间。App 后台也算得出 exp——不联网就能预判过期。

  2. 剩 6h · 转琥珀

    芯片变琥珀色提醒。此时离自动续期还有 4 小时，无需任何操作。

  3. T-2h · 自动续期

    调 GET /dsh-remote/url-session 换新 Bearer，芯片转圈。成功 → 回到 ~24h 绿态；失败 → 芯片转红「续期失败，请尽快重扫」，会话仍可用到当前 exp。

  4. 0h · 全屏失效页（屏 I）

    任何请求 401 或本地 exp 到点 → 该机器进入失效态：卡片变红内联"重新配对"，点入全屏页给出三因判别。仅此机器失效，其他机器不受影响。

  5. 重扫即恢复

    电脑端刷新二维码 → App 扫码 → 先验证后入库 → 回到 ~24h。30 天硬上限同理，只是二维码由"刷新"变为机器侧重新配对。

401 · 三因判别

relay 的 401 响应体是通用文案（remote session expired or missing），不区分原因——App 本地判别：exp 已过 = 24h 窗口过期；exp 未到但 401 = 被吊销或30 天上限（结合本地记录的第 N/30 天给出可能原因）。失效页文案随之变化，并清除该机器凭证、停止其续期调度。

WS 4001 · 被顶替

事件流被 close(4001, device_replaced) 掐断 → 顶部琥珀横幅「其他设备已配对，正在重连事件流…」，同一 Bearer 静默重连，恢复后横幅自动消失。不弹窗、不清凭证（HTTP 请求不受轮换影响）。

T-2h · 自动续期

到期前 2 小时调 GET /dsh-remote/url-session 换新 Bearer。倒计时芯片转圈 → 成功后时间刷新为 ~24h；失败转红提示「续期失败，请尽快重扫」，会话仍可用到当前 exp。网络恢复后自动补试。

配对验证失败

扫码后先验证后入库（屏 J）：首个 GET /dsh-remote/session 若 401，则二维码已过期或被替换——不写 Keychain，错误页指引回电脑端刷新。区分网络失败（重试即可）与 401（必须重扫）。

吊销确认

「吊销全部配对」与「断开中继」均为二次确认对话框，文案写明后果：吊销 = 所有设备立即失效（含当前手机）；断开 = 远程通道即刻不可用，需本机重连。

审批请求 · 会话中

agent 请求敏感操作（shell / 文件写入等）→ 对话流内嵌审批卡（屏 E）：操作类型 + 参数等宽展示 + 允许 / 拒绝，选择经 approval/request 事件流即时回传引擎。远程场景下这是高频且高价值的交互——不在场就永远批不了。

提问/选择 · 会话中

与审批并列且独立的第二类挂起交互（question）：agent 让你选——多问题批量作答、单选/多选、自由文本、可跳过（屏 P）；plan-review 特化= markdown 计划 + approve/decline 原样回传。挂起时占住 composer（输入栏变提问卡入口），审批同时挂起则两者并存、各自独立结算。前台提醒覆盖"agent 在等你回答"。

浏览器逃生舱 · 插件与长尾界面

插件管理面（Plugins/Models/Agent-presets 面板）远程被 PRIVILEGED 闸死——web 自己都隐藏（REMOTE_HIDDEN_NAV_SECTIONS），App 不做原生入口。插件运行面页面（定时任务、远程控制卡等）走「在浏览器打开完整 Web 界面」（屏 D）：App 调 GET /dsh-remote/url-session 铸新链接 → 系统浏览器打开完整 SPA。⚠️ 着陆会触发 v3.204 轮换（顶替其他浏览器 cookie 会话；App 自身 Bearer 不受影响）——按钮下方文案明示。v1.5 可换内嵌 WebView 容器（同一铸链路）。

中继不可达 ≠ 过期

超时 / DNS / TLS 失败一律标为「中继不可达」（琥珀，可重试），绝不与 401 混淆（红，需重扫）。证书指纹不匹配单独提示：证书已变更——确认非入侵后删除机器重新配对。

04

错误提示统一设计

错误是横切 14 屏的系统：同一套呈现层级、同一套文案模板、同一个错误对象模型——用户在任何屏遇到任何错误，语言和行为都一致。错误目录对着协议事实编写（401 通用响应体、relay 错误帧 engine_down / payload_too_large / concurrency_exceeded、429 限流、TOFU 指纹）。

① 四层呈现体系（按"需要用户做什么"分层，不按技术来源）
L1 · 全屏页
必须行动才能继续

会话失效（屏 I）、证书变更、存储不可用。红系。给出唯一主行动按钮。

L2 · 内联卡
上下文内就地处理

审批卡、任务失败卡（屏 F）、配对失败卡（屏 J）。嵌在相关内容旁，不打断全局。

L3 · 横幅
自动恢复 / 需要知道

中继不可达重试中、WS 4001 重连中、续期失败。琥珀系，恢复后自动消失，不打断操作。

L4 · SnackBar
短暂反馈与轻错误

操作成功（已吊销/已允许/已复制）、429 稍候重试、响应超限提示。数秒自消。

② 文案三段式（所有 L1/L2/L3 统一模板，zh/en 各一份资源键）
发生了什么（标题）一句、具体、不甩锅。✅「会话已失效」❌「出错了 (1001)」。zh：会话已失效 / en：Session expired
为什么（一行说明）用户视角的原因或边界，错误码/参数放等宽字体。✅「24h 窗口已过期（18:07）」❌「invalid token payload」
能做什么（行动）恰好一个主行动；可自动处理的写明"正在自动重试（第 N 次）"。绝不裸抛 JSON/stack/原始错误串。
③ 错误对象模型（App 内统一 ErrorCode，UI 只认它）
来源code呈现色重试行动

映射规则：HTTP 401 → auth.*（按本地 exp 判别细分）；429 → ratelimit；relay `error` 帧 → 按帧 code 直映射；TLS/超时/DNS → network.*（证书指纹不匹配特判 cert_changed）。未枚举的引擎错误 → L4 Toast + 原始消息等宽一行，不静默。全部错误入本地脱敏日志（token/psk 不落盘）。

④ 服务端错误契约——API 出码不出文案，UI 才出文案（relay 不做通用 i18n）
JSON 错误体（API 向）· 语言中立relay 给稳定 machine code + 参数（429 已带 limit/windowSeconds，是正面先例），prose 仅供调试。zh/en 文案只在 App 的 intl 资源里——relay 不知道客户端语言，也不该知道。
error 帧 · 已是契约形态engine_down / payload_too_large / concurrency_exceeded 机器可读 code 齐全，App 直映射；message 等宽兜底。无需服务端改动。
HTML 着陆卡 · 唯一双语点4 张卡（二维码无效/会话失效/无权访问/已被顶替）是 relay 唯一直接给人看的界面 → en/zh 双语静态表，默认 en、Accept-Language: zh 出中文。App 所有请求带 Accept-Language（与本机语言一致）。
401 加 code · v2 提案（向后兼容）v1 靠 App 本地三因判别（够用）；v2 给 401 体追加 code: session_expired | session_revoked | session_max_age | session_missing（原字段不动），判别变权威、App 与 SPA 共同受益，本地判别降级为兜底。
